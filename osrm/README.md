# OSRM (пешеходный маршрутизатор)

Используется сервисами `miklat-routes` (маршрут через несколько укрытий) и
`miklat-walking-routes` (маршрут до одного укрытия). Только пешеходный профиль
(`foot`) — в проде `shelter-route-planner` изначально пробовали `car`, он не
подошёл для сценария приложения, и остался только пешеходный экстракт
(см. `miklat-progress.md`, Фаза 1, шаг 4).

## Разовая подготовка данных

```bash
bash osrm/prepare-data.sh
```

Скрипт скачивает OSM-экстракт Израиля/Палестины с Geofabrik (~100–150 МБ) в
`osrm/data/` и прогоняет `osrm-extract` → `osrm-partition` → `osrm-customize`
через официальный Docker-образ `ghcr.io/project-osrm/osrm-backend` — ничего
не ставится локально, кроме самого Docker. Требуется сеть до
`download.geofabrik.de`. Первый прогон может занять несколько минут в
зависимости от скорости интернета и мощности машины.

`osrm/data/` — в `.gitignore` (это сгенерированные данные, десятки-сотни МБ,
им не место в git; воспроизводятся одной командой на любой машине).

## Запуск

После подготовки данных:

```bash
docker compose up -d osrm
curl "http://localhost:5001/route/v1/foot/34.78,32.08;34.7818,32.0853?overview=false"
```

Ожидаемый ответ — JSON с `"code":"Ok"` и посчитанным маршрутом. Если файлов
графа ещё нет в `osrm/data/`, контейнер `osrm` упадёт при старте — сначала
нужно прогнать `prepare-data.sh`.

## Почему один общий граф на два сервиса

`miklat-routes` и `miklat-walking-routes` — разные микросервисы (разная
бизнес-логика: множество точек через miklat_id vs произвольные две точки), но
дёргают один и тот же контейнер `osrm` по HTTP — пересобирать один и тот же
граф дважды смысла нет.
